# 实验分析与记录固定模板

本模板是项目中新增实验计划、实验记录和结果分析 Markdown 文档的固定格式。
所有必填项必须保留；无适用内容时填写“无”并说明原因，不得删除标题或留空。

文件名遵循：`{index}_{content}_{YYYY-MM-DD}.md`，其中 `index` 为两位递增序号，
`content` 使用简洁英文 `snake_case`。

保存位置按主要用途选择：计划放入 `review/plans/`，执行记录放入 `review/records/`，
结果分析放入 `review/analysis/`，交接与任务分发放入 `review/operations/`。
版本化实验记录必须继续按 `review/records/<method>/<environment>/` 分层；当前方法目录为
`apis_v2` 和 `apic_v3`，不得按 GPU 型号直接混放不同方法。
分类边界和当前索引见 `review/README.md`。

## 使用要求

1. 实验开始前填写“实验指导与依据”、判定标准和复现信息；结果产生后补充分析。
2. 结论必须能追溯到关联数据文件，不能只引用口头信息、截图或单个最优指标。
3. 比较实验必须说明基线、随机种子、数据划分及预先确定的通过/停止条件。
4. 关联文件使用仓库相对路径；外部大型产物同时记录稳定路径和 SHA-256。
5. 结果与预期不符时如实记录异常和局限，不得在查看目标域结果后改变判定标准。

```markdown
- 日期：YYYY-MM-DD
- 负责人：<姓名或账号>
- 状态：计划中 / 运行中 / 已完成 / 已终止
- Git commit：`<完整或至少 7 位 commit>`
- 关联文档：`review/<category>/...md`（无则写“无”）
- 关联数据文件：`outputs/...csv`、`outputs/...json`（无则写“无”）

## 1. 实验指导与依据

- 研究问题：<本实验要回答的唯一核心问题>
- 假设与基线：<预期变化，以及与哪个基线比较>
- 实施依据：<前序结论、协议、文献或数据证据；给出路径或引用>
- 实验范围：<任务、方向、方法、数据集、纳排规则>
- 判定标准：<运行前固定的主要指标、通过条件和停止条件>

## 2. 可复现记录

- 配置文件：`<仓库相对路径>`
- 数据与划分版本：<manifest/版本/校验值>
- 随机种子：<seed 列表>
- 环境与硬件：<操作系统、关键依赖、GPU>
- 启动命令：`<实际命令>`
- 工作区状态：clean / dirty（dirty 时列出相关改动）
- 产物位置：<仓库相对路径；外部产物写稳定路径、大小和 SHA-256>

## 3. 分析与结果

### 3.1 结果

| 方法/条件 | 主要指标 | 辅助指标 | 判定 | 备注 |
|---|---:|---:|---|---|
| baseline | | | | |
| proposed | | | | |

### 3.2 分析

- 相对基线：<报告绝对差值、跨 seed 稳定性及双方向差异>
- 异常与局限：<失败任务、缺失数据、环境差异、潜在偏差>
- 结果结论：<是否支持假设、是否达到预设判定标准>

## 4. 建议下一步实验指导

- 建议动作：<下一项最小且可验证的实验；无则写“停止并归档”>
- 建议依据：<本次哪些结果直接支持该建议>
- 固定条件：<下一步必须保持不变的配置、数据、基线和指标>
- 进入条件：<何时允许启动下一阶段>
- 禁止事项：<当前证据不足时不得开展的扩展或调参>
```

## 提交前检查

- [ ] 日期、Git commit、关联文档和关联数据文件均已填写。
- [ ] 实验依据、基线和判定标准在结果分析前已固定。
- [ ] 表格数值可由所列数据文件复核，失败和异常未被省略。
- [ ] 结论区分事实、解释与推断，没有用单一 seed 代替总体结论。
- [ ] 下一步建议包含依据、固定条件、进入条件和禁止事项。
