## 1. 文档目的

本文档将当前 Dual-Shift 结果转化为可直接执行的实验计划和可引用的论文决策边界，避免在证据尚未稳定时扩展任务、围绕目标域结果反复调参，或将单 seed 的局部正结果表述为双模块协同已经成立。

当前总决策如下：

- **不扩展** MCI vs AD、MCI vs CN 或三分类任务。
- **不以通过 target gate 为目的**调整 APIS 或 CDT。
- **冻结 postfix 配置**，先完成 APIS 双向 3 seeds（42/43/44，seed 42 已有）和 ADNI 同受试者 1.5T/3T 配对机制验证。
- CDT 暂不做性能导向扩展，只做 subject-level 风险、ESS、权重集中度、风险曲面和 missing 支持审计。
- Joint 暂停，直到单模块证据满足后续 Go 条件。

## 2. 证据范围与使用口径

### 2.1 当前正式证据

当前可用于正式决策的结果来自修复后的 postfix 实验，协议为 CN vs AD、双向迁移、seed 42、subject-mean 与 subject-row bootstrap。结果目录为 `outputs/journal/dual_shift_postfix/`。

必须明确以下限制：

1. **postfix 当前只有 seed 42**。所有数值均为单 seed 点估计及其受试者重采样区间，不能替代跨训练 seed 的稳定性证据。
2. **Stage2 修复前结果仅是历史探索**。`outputs/journal/dual_shift_stage2/` 中的结果不能作为正式性能证据，也不能与 postfix 混合汇总。
3. **论文和后续决策主表应使用带 DualShift 更新的版本**：`JOURNAL_RESULTS_with_dual_shift.xlsx`。旧主表若未包含 postfix 更新，不应作为当前数值来源。
4. postfix 的 `ds_ce` 与历史 Stage A 的 `weighted_ce` 并非完全相同的 backbone/采样器口径，因此跨阶段差值只能作辅助解释；模块门控必须使用 postfix 内部公平对照。

### 2.2 门控口径

- APIS gate：相对 `ds_ce` 检查 AUC 非劣、F1 提升和无塌缩。
- CDT gate：相对 `ds_ce` 检查 AUC 非劣和校准不双劣。
- Joint gate：相对 APIS/CDT 单模块，在 AUC、F1、Brier 三项中至少胜出两项。
- “双向通过”要求两个迁移方向均满足相应 gate；单方向通过不得写成整体通过。

## 3. seed 42 的确切结果与 gate 结论

### 3.1 APIS

**ADNI→NACC：**

- `apis_only` vs `ds_ce`：AUC **0.9239 vs 0.9228**，F1 **0.7770 vs 0.8077**，Brier **0.1316 vs 0.0976**。
- AUC 保持非劣，但 F1 明显下降，Brier 也更差。
- APIS gate 为 **fail**。

**NACC→ADNI：**

- `apis_only` vs `ds_ce`：AUC **0.9398 vs 0.8881**，F1 **0.8169 vs 0.7663**，Brier **0.1411 vs 0.1747**。
- AUC、F1 和 Brier 均改善，且无塌缩。
- APIS gate 为 **pass**。

**总体判断：** APIS 显示出明确但方向依赖的正信号；当前为一方向 pass、一方向 fail，因此不能宣称双向稳定有效。

### 3.2 CDT

**ADNI→NACC：**

- `cdt_only` AUC 为 **0.9094**，低于 `ds_ce` 的 **0.9228**。
- ECE **0.0849 vs 0.0727**、Brier **0.1057 vs 0.0976**，两项校准指标均变差。
- AUC 非劣与“校准不双劣”均未满足，CDT gate 为 **fail**。

**NACC→ADNI：**

- `cdt_only` AUC 为 **0.9125**，高于 `ds_ce` 的 **0.8881**。
- ECE **0.0942 vs 0.1309**、Brier **0.1550 vs 0.1747**，校准改善。
- CDT gate 为 **pass**。

**总体判断：** CDT 同样是一方向 pass、一方向 fail，双向总体为 **fail**。正向的 AUC 和两项校准同时变差，必须先排除权重机制的数值病态，不能直接进入性能调参。

### 3.3 Joint / DualShift

**ADNI→NACC：**

- `dual_shift` 的 AUC/F1/Brier 为 **0.9264 / 0.7872 / 0.1335**。
- Joint gate 为 **1/3，fail**：只有 AUC 构成胜项，F1 和 Brier 不支持协同优势。

**NACC→ADNI：**

- `dual_shift` 的 AUC/F1/Brier 为 **0.9133 / 0.8274 / 0.1346**。
- Joint gate 为 **2/3，pass**，但其 AUC **0.9133** 明显低于 `apis_only` 的 **0.9398**。

**总体判断：** Joint 一方向 1/3 fail、另一方向 2/3 pass，双边 gate 为 **fail**。当前证据不支持“APIS+CDT 产生稳定协同”，因此暂停 Joint 是必要的证据约束，而不是对模块的最终否定。

### 3.4 MixStyle

**ADNI→NACC：**

- `mixstyle` 的 AUC/F1/ECE/Brier 为 **0.9188 / 0.8105 / 0.0729 / 0.1036**。
- 相对 `ds_ce`，AUC 略低（0.9188 vs 0.9228），F1 略高（0.8105 vs 0.8077），校准接近但 Brier 更差（0.1036 vs 0.0976）。

**NACC→ADNI：**

- `mixstyle` 的 AUC **0.9150**、F1 **0.8310**、ECE **0.0496**、Brier **0.1244**。
- 其反向 AUC 低于 APIS 的 0.9398，但 F1、ECE 和 Brier 均优于 APIS（APIS 分别为 0.8169、0.0773、0.1411）。

MixStyle 没有单独的预注册模块 gate，不能人为补设 gate 后选择性宣称通过或失败。它在反向的表现说明：**APIS 尚未全面优于随机风格扰动**；APIS 的机制价值必须由多 seed 和同受试者配对验证共同支持，而不能只依赖一个方向的 AUC。

## 4. 当前可得与不可宣称的结论

### 4.1 当前可得结论

1. 在 seed 42 postfix 证据中，APIS 对 NACC→ADNI 有明确正信号，并通过该方向预设 gate。
2. APIS 的效果具有方向依赖性：ADNI→NACC 未通过 gate，主要问题是 F1 和校准/概率质量未改善。
3. CDT 未双向通过，且 ADNI→NACC 同时出现 AUC 下降和校准双劣，优先级应从“性能模块扩展”降为“机制与数值审计”。
4. Joint 未通过双边 gate；反向即使通过 2/3，其 AUC 仍低于 APIS 单模块，因此没有稳定协同证据。
5. MixStyle 是不可忽略的强对照，尤其在 NACC→ADNI 的 F1 和校准指标上表现突出。
6. 当前最有信息增益的工作是复现 APIS 的跨 seed 稳定性，并直接验证其是否改善同一受试者跨场强/协议的一致性。

### 4.2 当前不可宣称的结论

1. 不可宣称 APIS 已在双方向稳定提升跨队列泛化。
2. 不可宣称 APIS 全面优于 MixStyle；反向结果只支持 APIS 的 AUC 更高，不支持所有指标更优。
3. 不可宣称 CDT 已证明临床/人口偏移校正有效，或 CDT 的反向改善可泛化到正向。
4. 不可宣称 APIS 与 CDT 存在双模块协同，亦不可用正向最高 AUC 或反向 2/3 gate 选择性支持该说法。
5. 不可将单 seed、单任务、单方向结果推广到 MCI vs AD、MCI vs CN 或三分类。
6. 不可把 Stage2 修复前探索结果与 postfix 正式结果拼接成更强证据。
7. 不可把受试者 bootstrap 的置信区间解释为训练随机性已经得到验证；训练 seed 方差仍然未知。

## 5. 为什么暂不扩展任务

### 5.1 方法和选择规则尚未完全冻结验证

postfix 虽已完成关键修复，但尚只有 seed 42。此时扩任务会同时引入任务定义、类别组成、支持区域和训练随机性变化，使失败原因无法归因，也会增加在多个结果中反复选择配置的空间。

### 5.2 多 seed 证据缺失

单 seed 的方向差异可能来自训练随机性、模型选择或真实数据机制。必须先用完全冻结的 seed 43/44 判断 seed 42 的 APIS 正反向模式能否复现。

### 5.3 MCI 标签和类条件支持更困难

MCI 的诊断边界、随访状态和队列定义通常比 CN/AD 更异质。MCI vs AD、MCI vs CN 会改变类别条件下的 protocol/scanner 支持；三分类还会进一步增加类别不平衡、决策边界和校准难度。若 CDT 权重或 APIS 原型在 CN/AD 上尚未稳定，MCI 任务中的失败很难区分是模块问题、标签噪声还是支持不足。

### 5.4 多任务选择风险

提前运行多个任务、方向和变体，会提高“挑选最好任务/指标/seed”的研究者自由度，形成隐性多重比较和结果驱动的方法选择。正确顺序应是先冻结 CN vs AD 的方法和 gate，再按分级门控进入一个 MCI 先导，最后才做预注册的四任务确认。

## 6. 禁止 target-driven 调参与允许修复边界

### 6.1 原则

Gate 是用于裁决方法是否值得继续，而不是反向优化的目标函数。若看到 target 指标后再调整 APIS/CDT 直到过 gate，gate 将失去独立验证意义，并导致目标域泄漏和乐观偏差。

### 6.2 允许的实现或稳定性修复

仅允许与 target 表现无关、可由代码正确性或 source-side 数值诊断独立证明的修复，例如：

- 修复确定的实现错误、数据泄漏、subject 聚合错误、missing mask 错误或 checkpoint 加载错误。
- 修复非确定性来源并记录随机种子、数据顺序和软件环境。
- 处理明确的 NaN/Inf、溢出/下溢、除零、无效概率或损失不收敛。
- 在不查看 target 优劣的前提下，依据 source validation 和预注册规则处理 checkpoint 缺失、训练中断或等价重跑。
- 增加日志、断言和审计统计；增加机制评估但不改变模型输出。
- 对 CDT，仅在 source 侧出现预先定义的明确数值病态时，执行第 9 节规定的一次预注册稳定化修复。

任何修复都必须记录：触发证据、改动内容、预期影响、是否重跑既有 seed，以及修复前后结果不得选择性删除。

### 6.3 禁止的 target 驱动操作

- 根据 target AUC/F1/ECE/Brier 调 APIS 强度、warmup、原型更新、距离度量、层位置或损失权重。
- 根据 target 结果调整 CDT 温度、裁剪阈值、平滑、ESS 阈值、风险曲面或权重组合。
- 反复改变 checkpoint 选择公式、训练 epoch、早停规则或 collapse guard，直到 target gate 通过。
- 针对方向、任务或 seed 使用不同配置，并事后只报告最优配置。
- 查看 target 后决定删除某 seed、改变主要指标、改变 gate 或将失败指标降为次要指标。
- 用 target 标签进行阈值选择、校准拟合、超参数搜索或模型选择。
- 因 Joint 结果不佳而只对 Joint 单独更换 APIS/CDT 配置。

## 7. 最小下一步实验包

### 7.1 范围

只运行以下三个变体：

- `ds_ce`
- `mixstyle`
- `apis_only`

运行两个迁移方向：

- ADNI→NACC
- NACC→ADNI

训练 seeds 固定为：**42、43、44**。seed 42 使用现有 postfix 结果；seed 43/44 按完全相同配置补齐。除非发现可复现的实现错误，不重选 seed 42 配置。

### 7.2 冻结规则

在启动 seed 43/44 前冻结并留档：

- 数据 manifest、纳入排除规则、subject split 和预处理版本；
- backbone、采样器、batch 构造、优化器、学习率和训练日程；
- APIS 插入位置、原型更新/冻结、协议距离、损失权重和 warmup；
- MixStyle 参数与启用层；
- checkpoint 评分公式、collapse guard、早停和并列处理规则；
- 评估聚合方式、主要指标、bootstrap 方式和 gate 定义。

**Checkpoint 规则必须冻结且只使用 source validation 信息。** 每个 seed、方向和变体按同一评分公式选择唯一 checkpoint；禁止用 target 表现选择 epoch，禁止为不同变体人工挑选 checkpoint。训练失败仅可按事先定义的技术失败标准重跑，并保留失败日志。

### 7.3 必须报告的结果

对每个方向、每个变体：

1. 分别报告 seed 42、43、44 的 Acc、F1、AUC、SEN、SPE、ECE、Brier、WG-AUC。
2. 报告跨 seed 均值、标准差和方差；不得只报告最佳 seed。
3. 保留每 seed 的 subject-level 预测，支持配对比较和误差分析。
4. 报告 `apis_only - ds_ce`（APIS-CE）以及 `apis_only - mixstyle`（APIS-MixStyle）的每 seed 差值和跨 seed 汇总。
5. 按冻结规则逐 seed 判定 APIS gate，并给出方向级稳定性总结；不得仅以三 seed 均值掩盖方向或 seed 失败。
6. MixStyle 作为强对照完整报告，但不事后创设新 gate。

### 7.4 APIS 确认 gate

进入 MCI 先导的最低条件为：

- 两个方向均完成 3 seeds，无未解释的训练或 checkpoint 异常；
- APIS 在两个方向均满足冻结的 AUC 非劣、F1 提升、无塌缩 gate；
- 结论不能由单一 seed 驱动，且均值/方差与逐 seed 结果方向一致；
- 配对 1.5T/3T 机制评估至少不显示 APIS 系统性破坏同受试者一致性；
- 与 MixStyle 的比较按指标如实呈现，即使 APIS 只在部分指标占优。

若任一方向的确认 gate 失败，则不进入任务扩展，转入机制解释与论文范围收缩。

## 8. ADNI 同受试者 1.5T/3T 配对机制验证

### 8.1 配对原则

构建同一受试者的 1.5T/3T 扫描配对，优先限制在相同或尽可能接近的诊断状态和访视时间；报告配对数、时间间隔分布、诊断一致性、设备/站点组成和缺失原因。不得把不成对样本混入主要配对分析。

### 8.2 评估指标

对 `ds_ce`、`mixstyle`、`apis_only` 使用同一配对集合，至少评估：

1. **预测概率绝对差**：同受试者两场强预测概率的 \(|p_{1.5T}-p_{3T}|\)，报告均值、中位数、分位数和 bootstrap CI。越小表示协议变化导致的预测漂移越低。
2. **logit 差及有符号偏移**：评估场强是否产生系统性的预测方向偏差，而不只看绝对误差。
3. **预测类别一致率 / 翻转率**：在冻结阈值下统计同受试者是否因场强改变而发生分类翻转。
4. **配对排序或相关性**：报告两场强预测的 Spearman/Pearson 相关性，判断个体风险排序是否稳定。
5. **表征距离**：在冻结的特征层计算同受试者跨场强距离，并与非配对、同诊断受试者距离对照；检验 APIS 是否缩小协议差异而保留个体/疾病信息。
6. **场强可预测性**：用冻结表征做受控的 1.5T/3T probe；场强可预测性下降可支持协议信息被削弱，但必须同时检查诊断判别未塌缩。
7. **任务性能分层**：分别报告 1.5T、3T 子集上的 AUC/F1/ECE/Brier 和两者差值，避免总体指标掩盖某一场强退化。
8. **相对基线的配对改善**：逐 pair 比较 APIS-CE 与 APIS-MixStyle 的一致性变化，并用配对 bootstrap 或适当的配对检验给出不确定性。

### 8.3 机制意义

若 APIS 在不损害诊断判别和校准的前提下，稳定降低同受试者跨场强的概率、logit 和表征差异，可支持“APIS 学到 protocol-aware、protocol-robust 表征”的机制解释。若只提高跨队列 AUC，却不改善配对一致性，或通过抹除诊断信息降低场强可预测性，则不能据此宣称机制成立。MixStyle 的同配对结果决定 APIS 是否提供了超越随机风格扰动的特异机制证据。

## 9. CDT 审计与唯一允许的稳定化窗口

CDT 当前只做审计，不补多 seed 性能实验，不恢复 Joint。审计必须在 source 侧完成，target 仅用于冻结后评价，不得参与修复决策。

### 9.1 审计清单

1. **Subject-level 风险**
   - 确认权重和风险在 subject 层计算，重复扫描不会被当作独立受试者放大。
   - 检查每受试者扫描数与最终权重的相关性。
   - 按类别、队列、站点、协议和 missing 模式分层报告风险分布。

2. **ESS（有效样本量）**
   - 报告总体及类别条件 ESS、ESS/样本量比例，并随 epoch 追踪。
   - 检查是否由少量受试者承担大部分有效质量，及不同类别 ESS 是否严重不平衡。

3. **权重集中度**
   - 报告最大权重、分位数、top 1%/5%/10% 权重质量、Gini 或等价集中度指标。
   - 检查极端权重与类别、站点、协议、缺失和扫描重复数的对应关系。

4. **风险曲面**
   - 在 source 支持范围内绘制/汇总风险对关键协变量和组合协变量的响应。
   - 检查不连续尖峰、边界爆炸、反常单调性、稀疏区域外推和类别条件曲面断裂。

5. **Missing 支持审计**
   - 列出每个变量及组合 missing pattern 的人数、类别分布和站点/协议分布。
   - 验证 missing mask 的编码、传播和风险计算是否一致。
   - 检查无支持或近零支持模式是否仍获得高置信风险/极端权重。

6. **数值与训练稳定性**
   - 检查 NaN/Inf、权重归一化误差、梯度尖峰、损失震荡和 epoch 间权重排序稳定性。
   - 检查 source validation 性能是否与权重极端化同步恶化。

### 9.2 仅一次预注册稳定化修复

只有在 **source 侧**发现可复现、明确且预先量化的数值病态时，才允许一次稳定化修复。可接受触发包括 NaN/Inf、归一化失败、ESS 接近退化、极端权重集中或风险曲面出现明确数值爆炸；“target gate 未通过”本身绝不是触发条件。

修复前必须先锁定并记录：

- 病态定义和触发阈值；
- 唯一拟采用的修复（例如数值安全的归一化、预注册裁剪或平滑）；
- source-only 验收指标；
- 重跑范围和无论结果好坏均完整报告的承诺。

只允许这一轮稳定化。若 source 数值健康但 target gate 失败，则接受方法证据不足，不调参；若一次修复后仍病态或仍不满足后续 gate，则 CDT 停止作为性能模块，保留为审计/负结果。

---

## 10. 分级 Go / No-Go 决策

### 10.1 Gate A：APIS 双向 3-seed 确认

**Go：** 完成第 7 节最小实验包，APIS 双方向满足冻结 gate，结果不由单 seed 驱动，配对机制评估不出现系统性反证。  
**No-Go：** 任一方向持续 fail、结果高度依赖 seed、checkpoint/训练不稳定，或配对结果显示改善来自诊断信息损失。

No-Go 后停止扩任务；论文仅保留条件性/方向依赖结论，并围绕机制边界报告。

### 10.2 Gate B：一个 MCI 先导

只有 Gate A 通过后，才从 MCI vs AD 或 MCI vs CN 中**预先选择一个**先导任务。选择依据只能是标签定义质量、样本量、类别平衡和跨队列类条件支持，不能根据试跑 target 性能选择。先导沿用冻结的 `ds_ce`/`mixstyle`/`apis_only`、双方向和 3-seed 规则，并在运行前锁定 gate。

**Go：** 先导任务双方向达到预注册的 APIS 非劣/改善标准，无标签或支持审计红旗。  
**No-Go：** 任一方向出现稳定劣化、结果由单 seed 驱动、MCI 定义不可比，或类条件支持不足。

No-Go 后不运行另一个 MCI 任务“碰碰运气”，也不进入三分类。

### 10.3 Gate C：最终四任务、5-seed 确认

仅在 Gate A 和 Gate B 均通过后，进入最终确认。四任务指：

1. MCI vs AD：ADNI→NACC；
2. MCI vs AD：NACC→ADNI；
3. MCI vs CN：ADNI→NACC；
4. MCI vs CN：NACC→ADNI。

每个任务使用预注册的 5 seeds、冻结配置、source-only checkpoint 规则和统一报告模板。三分类仍需另行立项，不自动纳入。

**最终 Go：** 四任务均完成、主要结论跨 seed 稳定，预注册 gate 达标且没有不可解释的任务/方向异质性。  
**最终 No-Go：** 任一关键任务出现稳定负效应、支持不足、严重方差或需要任务特异调参才能过 gate。

### 10.4 全局停止条件

出现以下任一情况即停止对应扩展链：

- 需要查看 target 后修改配置、checkpoint 或 gate 才能获得正结果；
- APIS 双向 3-seed 确认失败；
- MCI 先导失败或标签/支持不可比；
- 配对机制结果与 protocol-aware 解释系统性冲突；
- CDT 一次稳定化后仍数值病态，或 source 健康但性能 gate 仍失败；
- Joint 不能在单模块均满足前置条件后证明增量价值。

## 11. 对论文主线的影响

### 11.1 APIS 通过、CDT 失败时

若 APIS 在多 seed 和配对机制评估中通过，而 CDT 仍失败，论文应转为 **protocol-aware 域泛化/鲁棒性** 主线：

- APIS 作为核心方法；
- `ds_ce` 与 MixStyle 作为必要对照；
- 同受试者 1.5T/3T 配对结果作为机制证据；
- CDT 降为人口/临床偏移的风险与支持审计，或作为诚实报告的负结果/局限性分析；
- Joint 不作为主方法，不使用“完整 Dual-Shift 协同”作为标题或核心贡献。

### 11.2 不得强行宣称双模块协同

只有当 APIS、CDT 单模块均通过预注册前置 gate，且 Joint 在双方向、多 seed 上显示相对两个单模块的稳定增量，才可讨论协同。当前 seed 42 结果不满足该条件：正向 Joint 仅 1/3，反向虽 2/3，但 AUC 0.9133 低于 APIS 0.9398。因此，任何“两个模块互补并共同提升”的强表述都超出证据。

若 APIS 多 seed 也未确认，则论文进一步收缩为方向依赖的探索性发现、强基线比较和机制/失败边界，不以方法全面优越为主张。

## 12. 最终执行优先级

1. **立即冻结 postfix**：配置、manifest、checkpoint 规则、gate 和报告模板全部留档。
2. **补齐最小实验包**：仅 `ds_ce`、`mixstyle`、`apis_only`，双方向，seeds 43/44；与既有 seed 42 合并报告。
3. **并行完成 ADNI 同受试者 1.5T/3T 配对机制验证**：统一配对集合，比较 APIS-CE 与 APIS-MixStyle。
4. **执行 CDT source-side 审计**：subject-level 风险、ESS、权重集中度、风险曲面和 missing 支持；无明确病态则不修。
5. **保持 Joint 暂停**：不补 seed、不调参，等待单模块门控。
6. **按 Gate A→B→C 顺序决策**：未过前一级，不启动后一级；当前不运行任何 MCI 或三分类任务。
7. **据确认结果选择论文主线**：APIS 确认且 CDT 失败，则转 protocol-aware 主线并将 CDT 降为审计。

**一句话决策：冻结 postfix，不为 target gate 调参；先以 APIS 双向 3 seeds 和同受试者 1.5T/3T 配对验证决定 protocol-aware 主线，CDT 只审计、Joint 暂停、MCI 与三分类暂不启动。**
